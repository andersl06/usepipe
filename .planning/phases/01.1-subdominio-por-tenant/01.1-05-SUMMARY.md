# 01.1-05 Summary

Traefik is pinned to v3.7.13 with fixed and tenant-host routers, including same-origin `/v1` and the `www` redirect. DNS-01 and HTTP-01 smoke modes are separate compose overrides. The DNS module now describes DNS-only apex, fixed-host, `*` and `*.desk` A records plus Let's Encrypt CAA, with the domain supplied by each environment.

Both deployment scripts select the TLS mode from `PIPE_DOMINIO_CONTAS` and share a preflight for domain syntax, exact cookie-domain pairing, no wildcard origin, central Google callback and Cloudflare token in DNS mode. The first-deploy script checks fixed and randomly chosen tenant DNS names against the VPS IPv4.

## Verification and limits

- Traefik v3.7.13 was the latest v3.7 release on the official release page on 2026-09-29.
- Git Bash syntax check passed for `bootstrap.sh`, `deploy.sh` and `tenant-domain.sh`; a valid domain passed preflight and a mismatched cookie was rejected with `PIPE_COOKIE_DOMINIO deve ser exatamente .example.app.`. `git diff --check` passed.
- Static scan found one service publishing ports (Traefik), no hard-coded domain in the changed compose/scripts/Terraform environment files, and no `proxied = true` in the DNS module.
- Docker was deliberately not executed under the owner's instruction, so compose merging and binary provider counts (`CF_DNS_API_TOKEN`, `HOSTINGER_API_TOKEN`) remain **unverified**. Cloudflare support is indicated by official Traefik/lego documentation, but is not a substitute for checking this image. Cloudflare absence must stop deployment; Hostinger absence only affects the fallback.
- Terraform CLI is unavailable here. `terraform fmt`, `init` and `validate` were not run; no plan/apply or DNS mutation was attempted. ShellCheck is also unavailable.

Before owner-run deployment: inspect the pinned image providers, run `docker compose config` with both overrides, and run `terraform fmt -check`/`validate` in the DNS module and both environments. No migration or database test was involved.
