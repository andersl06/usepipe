## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Barra de endereço → front | `window.location` é o host que a pessoa abriu (pode ser de outro tenant) |
| Build → bundle público | tudo que é assado no build é público e igual para todos os tenants |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-04-01 | Spoofing | link do Desk montado para um host que não é do tenant da sessão | mitigate | Função exige hostname começando com `<slug da sessão>.` e valida o resultado com o parse do plano 01; senão não mostra link |
| T-01.1-04-02 | Information disclosure | URL de um tenant assada no bundle compartilhado | mitigate | Build sem URL por tenant; verificação no bundle (`rg` no dist) |
| T-01.1-04-03 | Spoofing | Vite dev aceitando qualquer Host (DNS rebinding contra o dev server) | mitigate | `allowedHosts` restrito a `.lvh.me`, `.localhost` e ao domínio configurado; nunca `true` |
| T-01.1-04-04 | Tampering | proxy de dev reescrevendo o Host e mascarando o guard do plano 02 | mitigate | `changeOrigin: false`; coberto pelo roteiro de dev do plano 06 |
| T-01.1-04-05 | Spoofing | `returnTo` montado pelo front usado como redirect aberto | mitigate | Front só repassa; a API valida com `parseReturnTo` (plano 03) |
| T-01.1-04-06 | Denial of service | laço de redirecionamento entre host de tenant e login central | mitigate | O login central com sessão válida só redireciona para o tenant da própria sessão (que aceita a sessão); sem `returnTo`, não redireciona sozinho |
| T-01.1-04-07 | Tampering | `deniedTenant` usado para injetar texto na tela | mitigate | Só slug que casa `TENANT_SLUG_PATTERN`; renderizado como texto pelo React; teste com `<script>` |
</threat_model>
