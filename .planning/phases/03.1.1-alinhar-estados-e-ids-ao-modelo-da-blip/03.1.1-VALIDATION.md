# Fase 03.1.1 — Estratégia de validação

Contrato completo em `03.1.1-RESEARCH.md` (seção "Arquitetura de validação"). Resumo:

## Infraestrutura de teste

| Propriedade | Valor |
|---|---|
| Frameworks | vitest (core, db, api, bridge); `node --import tsx --test` (desk-vite, management-vite, crm) |
| Pré-requisito | Docker com Postgres e Redis ativos (testes de api e db) |
| Comando rápido | `pnpm --prefer-offline --filter @pipe/core test` |
| Suíte completa | `pnpm --filter @pipe/api test` + `typecheck` de cada app/pacote (plano 12) |

## Taxa de amostragem

- Após cada tarefa: teste alvo do plano (comando `<automated>` da tarefa).
- Após cada onda: testes dos pacotes tocados.
- Antes de `/gsd:verify-work`: suíte completa verde e grep final de literais antigos vazio fora de `drizzle/`.
- Testes de migration (0084, 0091) rodam em transação com rollback; não rodar em paralelo com outras suítes que usam o mesmo banco.
