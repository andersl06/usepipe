# Fase 03.1.1 Plano 14: Link assinado na entrega de anexos e log de requisições — Resumo

Anexo enviado pelo atendente agora chega à Meta por `PIPE_URL_API/v1/attachments/:id?expires&signature`, gerado pelo worker no momento da entrega com a mesma função que a API usa (G-14), e a API passa a registrar uma linha JSON por requisição, sem query, corpo, cookie nem Authorization (G-15).

## Task 1 — Link assinado da API na entrega de anexos (commit `841b107a`)

Causa do 131053 em produção: `urlOfMedia(anexo_chave)` concatenava `PIPE_STORAGE_URL_BASE` (`https://pipebr.app`, o site) com a chave de storage. O mesmo vale para a API: `linkOfAttachment` preferia `PIPE_STORAGE_URL_BASE` a `PIPE_URL_API`, então o link devolvido no upload também apontava para o host errado quando a variável existia no ambiente.

O que mudou:
- `packages/storage/src/porta.ts`: `segredoDeLink(chaveiro)` (derivação do segredo a partir do chaveiro, antes privada da API), `baseDoLinkDeAnexo(env)` (`PIPE_URL_API`, fallback `http://localhost:3000`) e `linkAssinadoDeAnexo({ anexoId, segredo, base, agora })`. Reaproveita `assinar` e `VALIDITY_LINK_MS` (15 min); o algoritmo não foi duplicado.
- `apps/api/src/domain/attachment.ts`: `linkOfAttachment` e `secretOfLink` passam a chamar essas funções.
- `apps/workers/src/delivery.ts`: a consulta de entrega seleciona `a.id as anexo_id` (no lugar de `chave_storage`); `montarConteudo` monta `linkDeAnexo(anexo_id)` com `keyringOfEnvironment()` + `baseDoLinkDeAnexo()`. O link é gerado a cada tentativa, então reentrega do outbox horas depois recebe link novo. `urlOfMedia` foi removida; mídia de fluxo continua usando a URL absoluta declarada em `dados.midia.url`. `montarConteudo` e `LinhaDeEnvio` passaram a ser exportados para teste.
- `apps/workers/package.json` + `pnpm-lock.yaml`: dependência `@pipe/storage` (workspace). `apps/workers/Dockerfile`: `COPY packages/storage/package.json` no estágio de manifestos (o `--frozen-lockfile` confere o workspace inteiro).
- Testes da API (`attachments.test.ts`, `attachments-multiplos.test.ts`) passaram a definir `PIPE_URL_API` em vez de `PIPE_STORAGE_URL_BASE`.
- `infra/compose/env.prod.exemplo` e `.env.example`: comentários atualizados.

Teste novo `apps/workers/tests/delivery.test.ts` (4 casos): link aponta para a API (origem + `/v1/attachments/<id>`), sem a base do storage nem a chave; `expires` dentro de 15 min; `assinaturaValida` da API aceita com o mesmo segredo e recusa com outro id, outro segredo e depois de expirar; mídia de fluxo mantém a URL absoluta; sem chaveiro devolve `anexo_link_indisponivel` sem lançar.

## Task 2 — Log de requisições da API (commit `16e0ea40`)

`apps/api/src/request-log.ts`: middleware Express registrado em `createApplication` como o primeiro da cadeia (antes do CORS). Ao fim da resposta escreve em stdout uma linha, por exemplo:

`{"ts":"2026-10-05T22:04:34.204Z","evento":"requisicao","metodo":"GET","rota":"/v1/attachments/:id","status":200,"ms":12.4}`

- Campos: `ts`, `evento`, `metodo`, `rota`, `status`, `ms`, e `tenantId` / `usuarioId` quando a autenticação os pôs na requisição (`request.session` ou `request.context`). `abortada: true` quando o cliente fechou a conexão antes do fim (long poll do Desk).
- Rota = padrão do Express (`req.route.path`, com `baseUrl`); sem rota casada, o caminho sem query string.
- Nunca grava query, corpo, cookies, Authorization nem outro header.
- Pula `/saude`, `/health` e `/metrics`. `PIPE_LOG_REQUISICOES=0` desliga (qualquer outro valor, ou ausente, deixa ligado).

Teste `apps/api/tests/request-log.test.ts` (9 casos) com servidor Express real: formato e campos, padrão de rota sem o id, chave de API sem usuário, requisição anônima sem tenant, rota inexistente sem query, ausência de assinatura/token/cookie/corpo/`?` na linha e conjunto exato de chaves, sondas puladas, duração em ms, e desligamento por env.

## Variáveis de ambiente do serviço `workers` (docker-compose de produção)

O serviço `workers` usa `env_file: [/opt/pipe-dados/.env]` (âncora `x-app`), sem `environment` que restrinja variáveis, então ele recebe o mesmo `.env` da API. O worker agora PRECISA ter, com os MESMOS valores que a API:

1. `PIPE_URL_API` (por exemplo `https://api.pipebr.app`): base do link. Antes o worker não lia essa variável.
2. `PIPE_CHAVES_SEGREDO` e `PIPE_CHAVE_SEGREDO_ATUAL`: o chaveiro de onde sai o segredo da assinatura. O worker já os usava para decifrar o token do canal; agora também assinam o link, então tem de ser exatamente o chaveiro da API (senão a API devolve 401 "Link inválido ou vencido").

Nenhuma variável nova foi criada. Se o `.env` compartilhado já tem as três (o `env.prod.exemplo` tem), nada a acrescentar; basta conferir no deploy. Opcional: `PIPE_LOG_REQUISICOES=1` (já é o padrão) ou `0` para desligar o log na API. `PIPE_STORAGE_URL_BASE` pode ser removida do `.env` da VPS: nenhum serviço a lê mais.

Deploy: precisa reconstruir a imagem do worker e a da API (a dependência `@pipe/storage` entrou no worker).
