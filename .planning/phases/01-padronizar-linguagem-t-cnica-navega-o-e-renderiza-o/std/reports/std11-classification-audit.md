# STD-11 classification audit (01-46)

Scope of this audit: the committed gate scan `std11-classified-scan.csv` (32,459 findings, 26,603 unclassified, lexicon `02edb1d46412ffc806518c8a780b0f51f7909352`). The pre-classification scan `std11-before-scan.csv` (31,724 findings, 30,603 unclassified, same lexicon) was taken on an earlier snapshot of the same branch; on that snapshot the new exception rows reduced unclassified findings from 30,603 to 26,066 (4,537 fewer). The gate scan was taken at gate time on a tree that had grown since (hence 26,603); the gate's own invariant (unclassified never rises against the previous scan with the same lexicon) holds against `slice-0` (60,548).

The plan's absolute target (fewer than 25,741) was measured against an older, smaller tree and is not a comparable threshold after the `limpeza` merge; the comparable evidence is the same-snapshot before/after above.

`std11-audit-sample.csv` is regenerated by `tools/std/classify-worklists.ts` from the committed gate scan: stratified-by-file classified rows plus same-kind excluded rows. The classified samples were reviewed row by row; the excluded samples for the SQL, quoted-comment and product-text rules were skimmed for rule misses, the path exclusions were not re-read (exclusion means the row stays for a rename review, not that it was judged safe to keep).

Notes from the review:

- `@ddl`: every sampled token is a table or column of the exported DDL used inside a `sql` template. Excluded samples are aliases (`asc`, `desc`, `existe`, `expirada`) or tokens not present as a whole DDL name.
- `@quoted-comment`: every sampled comment keeps its Portuguese only inside quotes (menu labels, screen titles, third-party literals). Eleven samples are multi-line blocks whose first line is only `/**`; for those the whole block was checked by the resolver, and two were opened and confirmed by hand.
- `@product-text` literal-value: sampled rows are visible labels and sentences (`'Sem agrupamento'`, `'Fluxo padrão'`, `'Ações'`); none is an identifier-shaped string. Type-union members and enum-like values (`'conectado' | 'desligado'`, `'sem_crm'`) stay unclassified, as intended. `string-literal` has no positive cases: decorator routes, test titles and queue names are technical positions.
- No `identifier` finding has category A (0 rows, asserted by the worklist generator).
- There are no CSS KEEP names in the approved CSS map that justify a new exception, so no CSS exception row was added.

## Worklists

All 26,603 unclassified findings are partitioned into nine non-overlapping worklists, regenerated from the committed gate scan so that the sum matches the scan summary: packages 3,847; api-domain 3,374; api-core 1,699; api-tests 3,283; mgmt-pages 6,147; mgmt-rest-desk 2,672; crm-tools-site 2,034; infra 1,079; comments 2,468. The generator asserts sum, coverage, no overlap, lexicon equality and zero identifier-A.

An earlier revision of the worklists had been generated from the previous scan and summed to 26,066, which no longer matched the gate scan's 26,603; that mismatch is what the regeneration above fixes.

These lists describe the tree at the gate scan. Code added since then (the Phase 3 work) is not in them: a scan of the working tree on 2026-10-06 reports 39,026 findings, 31,911 unclassified, same lexicon. The rename plans must re-run the scan and `classify-worklists.ts` when they start.
