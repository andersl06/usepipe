<objective>
Classificar em massa, por regra e com auditoria, os achados do STD-11 que não são identificador técnico (SQL persistido, texto de produto, caminhos persistidos/públicos), fazer o re-baseline explícito do gate e dividir o resto em listas de trabalho por escopo para os planos de rename (D-53, parte 1).

Output: resolvedores no scan-pt, linhas novas em exceptions.csv, gate `std11-classified`, worklists por escopo.

Model routing: Task 1 Codex CLI conta 1 (`gpt-5.6-sol` medium) para os resolvedores com testes; Task 2 Sonnet (escrever as regras de exceção, auditar amostras e decidir fronteiras A/B/C é trabalho de julgamento, D-24/D-25).

Fato verificado no planejamento (corrige o `01-CLOSURE.md`): o hash `Lexicon:` do scan vem de `std/reports/gate2-lexicon.txt` (`tools/std/scan-pt.ts:212-214,424`, passado pelo `gate.sh` via `--lexicon-file`), NÃO de `exceptions.csv`. Editar exceptions.csv baixa `Unclassified` sem mudar o hash, o que o passo `pt-scan` do gate aceita (só falha se subir). A armadilha real é mexer em `gate2-lexicon.txt`: aí o gate exige rótulo `baseline`/`slice-0`. Este plano NÃO toca `gate2-lexicon.txt`. Hoje `gate-order.txt` só tem `baseline` e `slice-0` (60.548); o gate `std11-classified` vira o piso que todos os gates seguintes comparam.

Decisão tomada (D-35 prevalece sobre a sugestão do CLOSURE): classes CSS e custom properties em português são identificador técnico pelo D-35. Só entram como exceção as que têm linha aprovada `KEEP` no mapa CSS (ex.: estados `alerta`/`sucesso` se o mapa aprovado as manteve) ou que são nome literal de terceiro/Blip copiado com evidência (D-17). O resto (≈2,7 mil, `conteudo`, `campo`, `botao`...) vai para rename nos planos de front com `tools/std/rename-css.ts`. Se o dono preferir classificar os compostos como C, a mudança é trocar a worklist CSS por uma linha de exceção nesta task.
