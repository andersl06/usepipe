- Implement only the behavior the investigation proves; unknowns go to the deferred list instead of being invented.

### Delivery shape
- One atomic commit per owner point, English identifiers/commits/docs; chat with the owner in Portuguese.
- Work on the current branch `fix/ajustes-visuais-gestao` (no worktrees, no extra folders).
- Do not touch files owned by parallel sessions: Desk, attendance core, attachments, migrations 0092+. Where a point needs them (9, 10), coordinate by keeping changes additive and isolated.
- Order: quick wins and verifications first (1, 12, 7), then investigations that unblock others (3 → 2, 4 → 8 → 9), then audits (10, 11), then larger builds (5, 6, 13).

### Contacts identity (7)
- Router shows the channel identity (e.g. `5521972570484@wa.ms`; Instagram format differs) as the contact label; flow shows channelId. Confirm in Blip before coding.

### Logs / history (8, 9)
- Match Blip filters and displayed fields; show logs even when logging is disabled if Blip does; history limited to 90 days; distinguish conversations by ticket, with ticket info shown as Blip does.

### Analytics (4)
- Flow analytics and router analytics are different surfaces; reuse existing flow/router data. Apply Blip's search-limit rules (report manager 90 days / 5 years) and check whether other reports have limits.

### Pipe Chat (6)
- Embeddable web-chat widget analogous to Blip's web chat; minimal viable embed (script snippet + channel config + messaging round trip) in its own plan, after the other points.

### Claude's Discretion
